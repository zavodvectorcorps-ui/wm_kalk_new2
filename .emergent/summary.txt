**Key Technical Concepts**
-   **API-backed Webhook**: Implemented a pattern where a lightweight webhook from amoCRM triggers a more data-intensive API call back to the source system (amoCRM) to fetch full entity details. This is a robust way to handle webhooks that don't contain all necessary data.
-   **Dynamic vs. Static Forms**: A recurring bug was resolved by replacing a dynamic, database-driven form () with a hardcoded static form (), highlighting the trade-offs between flexibility and reliability.
-   **Stateful Geocoding**: On the frontend, orders are now geocoded upon loading, and their coordinate data is stored in the component's state, allowing for immediate map visualization and status indicators.
-   **Frontend State-based Filtering**: The application now filters the main order list based on whether an order is part of a trip, managing visibility entirely on the client-side state after the initial data fetch.
